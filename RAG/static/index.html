How RAG Actually Works Under the Hood

Standard LLMs are generalists. They cannot read your internal wikis, proprietary specs, or private databases. RAG decouples knowledge storage from reasoning:

R

1. Retrieval

Bi-Encoder + Vector DB

Maps documents into vector embeddings. Given a query, it computes cosine similarity to identify candidate chunks. (Advancement: HyDE + Cross-Encoder Re-Ranking).

A

2. Augmentation

Context Window Engineering

Constructs a prompt injecting the retrieved facts and grounding constraints: "Answer using ONLY this context". (Advancement: Lost-in-the-Middle U-Shaped Ordering).

G

3. Generation

Gemini Synthesis + Citations

Gemini reads the prompt and synthesizes a grounded answer citing the source chunks. (Advancement: Self-RAG automated claim verification pass).

What Most People Don't Know: 5 Advanced RAG Truths

State-of-the-art developments, real-world failure modes, and recent advancements.

1. The Question-Answer Vector Asymmetry

In naive vector search, you embed a question and compare it to answer chunks. But questions have completely different grammatical structure and vocabulary than expository documents!

Solution: HyDE generates a hypothetical answer passage first, so you compare document vectors to document vectors.

2. The "Lost in the Middle" U-Curve

Stanford researchers proved that even with a 1M token context window, LLMs suffer attention degradation on facts placed in the middle of prompts. Performance drops by up to 50%!

Solution: Context re-ordering puts the highest-scoring chunks at index 0 and index N-1 (the U-shape).

3. 2-Stage Retrieval (Re-Ranking)

Vector databases use Bi-Encoders (embed query and doc separately). It's fast (10ms over 1M docs) but inaccurate. Production RAG uses a Cross-Encoder Re-Ranker on the top 20 candidates.

Impact: Boosts Hit-Rate@3 accuracy by 25-35% in enterprise benchmarks.

4. Dense Vectors Fail at Negation & IDs

Cosine distance cannot handle logic operators like "Show invoices NOT from Acme" or exact part numbers ("Error code 0x8007"). Vectors place "Acme" close to "NOT Acme".

Solution: Hybrid Search (BM25 lexical search + Dense Vectors fused via Reciprocal Rank Fusion).

5. GraphRAG & Agentic RAG (2024-2026)

Standard RAG fails at global queries like "What are the main themes across all 500 reports?". GraphRAG (Microsoft) extracts knowledge graphs and community clusters to answer global corpus questions.

Agentic RAG: An LLM agent plans multi-step retrieval queries iteratively instead of a single search.

6. The Chunking Dilemma

If chunks are too small (100 words), context is lost. If chunks are too large (1,000 words), the embedding vector becomes "muddy" and diluted.

Modern Solution: Parent-Child chunking (embed small child chunks for search, pass larger parent chunk for generation).
